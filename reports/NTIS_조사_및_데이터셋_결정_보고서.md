| # | 시나리오 | 라벨 정의 | 활용 변수 | 강의 매칭 | 현실성 (오늘 마감 기준) |

### 3.5 NTIS 옵션의 리스크 정리

1. **🔴 Critical: 마감 시점 데이터 확보 불가능.** OpenAPI 인증키는 신청 후 1–수일 소요. 마이크로데이터는 수주 단위. 오늘 23:59까지 데이터 셋업 → EDA → 베이스라인까지 가는 건 **물리적으로 불가능**하다.
2. **🔴 Critical: Kaggle 등재 안 됨.** 강의 명세 "You can choose the dataset freely from **Kaggle datasets**" + 제안서 "Kaggle URL 제출" + originality "**Top 3 upvoted 노트북과 비교**" — NTIS는 이 셋 모두 충족 못함. 사용하려면 사전 TA·교수 승인 필요. 오늘 받을 수 있을지 불확실.
3. **🟡 Risk: 참고논문(FAPESP)의 정확도 자체가 67% 수준.** 그 결과를 한국 NTIS로 옮긴다고 더 좋아진다는 보장 없음. 평가 70% 항목인 "insight from results"가 약해질 가능성 큼.
4. **🟡 Risk: 강의 토픽과의 매칭이 약하다.** NLP 텍스트 마이닝으로 빠지면 LR/LDA/QDA/PCA 같은 강의의 핵심 토픽을 자연스럽게 활용하기 어렵다. DL 단독 사용 시 감점 명시.
5. **🟡 Risk: 선행 논문이 이미 있다.** "AI 기반 신약개발 NTIS 5,610건 텍스트마이닝(TF-IDF+LDA)" 등 한국어 NTIS 데이터 분석 논문이 이미 존재. 차별성 입증 어려움.
6. **🟢 장점은 분명히 있다.** 도메인 스토리("정부 R&D를 어떻게 더 잘 굴릴까")는 입체적이고, 발표할 때 매력 있음. **그러나 평가 기준에 직접 점수가 되지는 않는다.**

## 5. 최종 추천

### 🥇 1순위 — SECOM (Kaggle: paresh2047/uci-semcom)

**왜 이걸 1순위로 두는가:**
- **591변수 × 1,567샘플 + 6.6% 양성 + 5–60% 결측**이라는 조합이 강의의 모든 토픽을 한 데이터셋에 자연스럽게 욱여넣는 거의 유일한 케이스다.
- 결측 처리 3종(제거/중앙값/KNN), 클래스 불균형 처리 2종(가중치/SMOTE), 차원 축소 3종(분산 임계/PCA/트리 중요도), 분류기 5종(LR-L1/L2/LDA/QDA/SVM), 앙상블 2종(RF/GB), NN, 스태킹, ROC-AUC/PR-AUC/운용점 평가 — **전부 자연스럽게 들어간다**.
- **변수가 익명**이라 도메인 지식 의존이 없음 → 분석 자체의 깔끔함이 살아남.
- **Kaggle에 명시적으로 등재**되어 있어 제안서의 "Kaggle URL"과 "Top 3 upvoted 노트북" 모두 즉시 충족.
- 인기 노트북 대부분이 "RF/XGBoost + SMOTE → 점수 한 줄"이라 **단계별 ablation 자체가 강력한 originality 차별점**.
- 데이터가 작아(1,567행) **CV·하이퍼튠을 모두 마감 내 충분히 돌릴 수 있다.**

### 🥈 2순위 — KAMP 사출성형 (백업안 1)

- 88만 행이라 데이터 풍부, 27변수로 PCA 시각화도 깔끔.
- KAIST/UNIST 공식 가이드북(AE/SVM/DNN)이 있어 baseline 비교가 명확.
- **단점:** Kaggle 등재가 아니므로 KAMP의 라이선스·출처를 제안서에 명시해야 함. "Top 3 upvoted 노트북"은 채우기 어려움 (KAMP 가이드북으로 대체 설명 가능).

### 🥉 3순위 — KAMP 냉간단조 (백업안 2)

- 매우 낮은 양성비 → 운용점(Precision-fixed Recall) 분석이 가장 의미 있음.
- XGBoost 가이드북 → 우리의 ablation과 직접 비교 가능.
- 단점: 사출성형과 마찬가지로 Kaggle 등재 아님.

### 4순위 — KAMP CNC (백업안 3)

- 9.6만 행이라 다른 KAMP 대비 작고 차별점 약함.

### ❌ 5순위 — NTIS (비추천)

- 위 §3.5의 6가지 리스크 중 **앞 두 개(마감·Kaggle)가 결정적**.
- 도메인 매력은 분명하지만, 학기 텀프로젝트 평가 기준에 직접 가산점이 되지 않는다.
- **만약 팀원 1이 NTIS를 강하게 밀고, 시간이 충분하다면** Application Project가 아니라 별도의 학회·대회용으로 진행하는 게 더 효율적이다.

## 6. 팀원 1에게 보낼 회신 요지 (제안)

> 1. NTIS 데이터를 직접 한 번 다 돌아봤다. 카탈로그 자체는 풍부하다(과제·논문·특허·보고서·사업화·기술료·연구자·기관 등 11개 큰 카테고리).
> 2. 그런데 마감(오늘 23:59) 안에 라벨이 붙은 정형 ML 데이터셋을 만들기엔 절차가 길다. 마이크로데이터 신청은 수일~수주, OpenAPI는 메타데이터 검색 단위라 라벨 매핑이 자동이 아니다.
> 3. 강의 명세가 "Kaggle 데이터셋, Top 3 upvoted 노트북 URL 제출, 그 노트북들과의 차별점으로 originality 평가"를 명시하고 있어, NTIS는 사전 승인이 필요하고 그 승인을 오늘 받기 어렵다.
> 4. 참고논문(FAPESP)의 정확도가 67% 수준이라 NTIS로 옮긴다고 인사이트가 더 명확해진다는 보장이 없다.
> 5. 그래서 텀프로젝트는 SECOM(또는 KAMP 사출성형)으로 가고, NTIS는 후속 연구나 졸업프로젝트로 따로 키우는 걸 제안한다.

## 8. 부록 A — NTIS 데이터로 미래에 시도할 만한 연구 토픽 (참고)

마감 후 학회·대회용으로 따로 가져갈 수 있는 아이디어 메모:

1. **한국형 grants productivity 예측 (FAPESP 한국판).** NTIS 마이크로데이터를 정식 신청해서 PI별 누적 출판/인용/grant/협업/기관 변수를 만들고, 부처·분야별로 구분해 분류기 비교. 67%를 넘기는 게 목표.
2. **사업화 성공 vs 실패 예측.** 성과활용현황조사 + 기술료 데이터를 조합해 "사업화 성공" 라벨을 만들고, 과제 메타·연구자 이력으로 예측. 실용성 강함.
3. **과제 요약문 분류 + 부처별 키워드 트렌드.** 전체 과제 요약을 BERT/SBERT 임베딩 → 부처·세부사업 분류 + 시계열 토픽 트렌드. (강의 범위 밖이라 텀프로젝트엔 부적합)
4. **연구자 협업 네트워크 + 성과 예측.** 공동저자 그래프에서 그래프 ML로 미래 grant 성공률 예측. 연구실 졸업 프로젝트급 규모.
